# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

MiyoCalc40 is a through-hole-only RPN calculator: a hardware + firmware project, not a typical software repo. The repository has two independent halves:

- `MiyoCalc40_firmware/` — C/C++ firmware for the calculator's AVR128DA28 MCU, built with a plain `avr-gcc`/`make` toolchain (no Arduino IDE or vendor board package).
- `pcb/` — KiCad hardware design (schematic, PCB layout, footprints, BOM).

There is no shared build system between the two; treat them as separate projects sharing a repo.

## Firmware: build & flash

Build and flash from the command line — no Arduino IDE, no vendor board package. Edit in any
plain text editor (Kate, etc.); `MiyoCalc40_firmware/.clangd` + `compile_commands.json`
(regenerated by `make bear`) give clangd-based editors navigation, though its AVR diagnostics
are unreliable (false positives on register writes like `PORTx.OUT = ...`) — `make`/`avr-gcc`
is the only authoritative compile check.

- Toolchain: system `avr-gcc`/`avr-g++` 14.3.0 + avr-libc 2.2.1 — natively supports AVR128DA28
  (`/usr/lib/avr/include/avr/ioavr128da28.h`), no vendor device pack needed — and avrdude 8.x
  (native `avr128da28` part + `serialupdi` programmer, no Python/pymcuprog).
- Target MCU: **AVR128DA28** at 24 MHz, configured explicitly by `avrducore/clock.c`'s
  `clock_init()` — there is no vendor core silently doing this anymore.
- Run from `MiyoCalc40_firmware/`:
  - `make` — builds `build/MiyoCalc40_firmware.hex` (`-Os`).
  - `make flash` — flashes over UPDI (`/dev/ttyUSB0`). Physically rewrites the device — treat as
    a deliberate action requiring the user's go-ahead, not a default step in a larger task.
  - `make flash_fuses` — writes the fuse row from `avrducore/fuses.c`. Separate from
    `make flash`, since fuses are a one-time/rare, higher-risk write.
  - `make debug` — `-O0 -g` build under `build/debug/` (doesn't touch the normal build's
    objects), for readable `avr-objdump -d -S` disassembly when `-Os`'s CSE/unrolling makes a
    bug hard to trace by hand.
  - `make bear` — regenerates `compile_commands.json`.
  - `make format` — astyle per `.astylerc` (run-in braces, mirrors the KeyDU-Citrouille90
    project's convention). The existing code does not follow that style, so a real run
    reformats nearly the whole tree — treat as its own deliberate, isolated commit.
  - `make help` — lists all targets.
- There is no unit test suite, linter, or CI for the firmware — verification is done on real
  hardware.

### avrducore/ — hand-rolled replacement for the Arduino core

With no Arduino/DxCore `init()`, `avrducore/` supplies what it used to provide silently:

- `clock.c`/`clock.h` — `clock_init()`: 24MHz OSCHF, no prescaler, via CCP-protected writes.
- `ccp.S`/`ccp.h` — the CCP-protected register write helper (`ccp_write_ioreg()`) clock init
  needs; device-independent, copied from the KeyDU-Citrouille90 project.
- `fuses.c` — the fuse row (`FUSES` struct → the linked `.fuse` ELF section), written via
  `make flash_fuses`. AVR128DA28's `SYSCFG0` has no `UPDIPINCFG` field (unlike the DU-series
  `fuses.c` this was modeled on) — don't copy that field in if cross-referencing that project.
- `gpio.h` — a `gpio_pin_t` (port + bitmask) pin descriptor and `GPIO_*` macros, replacing
  Arduino's `digitalWrite`/`digitalRead`/`pinMode`.
- `spi.c`/`spi.h` — a minimal SPI0 master driver (fixed 6MHz/mode 0/MSB-first), replacing
  `<SPI.h>`.

`main()` calls `clock_init()` directly instead of DxCore's `init()`; delays use avr-libc's
`<util/delay.h>` (`_delay_ms()`/`_delay_us()`) instead of Arduino's `delay()`.

### Compiler / `double` width

`double` is 32-bit (`== float`, avr-gcc's default `-mdouble=32`), giving ~7.2 honest decimal
digits of precision. `precision` in `calc.cpp`'s `calc_init()` is set to `7` to match,
deliberately staying inside that budget.

**Do not add `-mdouble=64` to the makefile without hardware-verifying first.** This was tried
under the old Arduino/DxCore build and reverted: it compiled and linked cleanly with no errors
(`__adddf3`/`__muldf3`/`__divdf3` all resolve fine — those come from libgcc, not avr-libc), but
avr-libc 2.2.1's `log10()`/`floor()`/`round()` for 64-bit doubles resolve to a software "libf7"
extended-precision library (`__f7_log10`, `__f7_floor`, `__f7_round`) that produced garbage
results on real AVR128DA28 hardware — e.g. `LCDNumber(3.0)` computed `_exponent` around
`-22003` instead of `0`. This is invisible to linkage checks and to host-side testing (the
host's own `double` math is correct; only the AVR target's is broken), so it can only be caught
by running on real hardware. The makefile makes `-mdouble=64` trivially easy to add (just
another `CFLAGS`/`CXXFLAGS` line) — if revisited, verify `log10`/`pow`/`floor`/`round`
numerically **on real hardware** (e.g. print results over UART) before trusting a clean build.

## Firmware architecture

The module breakdown and dependency order is documented in the header comment of `main.cpp` and in `main.h`:

- **main.cpp/h** — `main()` (init + `loop()` dispatch), `loop()`, MCU/sleep setup, port ISRs. `loop()` is the core state machine: sleep the CPU, wake on a column-pin interrupt, debounce (10×2ms), scan the matrix, then dispatch the pressed key.
- **matrix.cpp/h** — keyboard matrix scanning (`scanKB()`), exposes the currently-pressed `keypos_r`/`keypos_c`.
- **cards.cpp/h** — maps matrix key positions to `action` structs (keycode + function pointer + display mnemonic). A "card" is a swappable keymap (e.g. algebra, trig, finance) with a base layer plus `f`/`g`/`h` shift layers (see `enum layers`). `keytoaction()` is the lookup entry point called from `main.cpp`'s loop.
- **calc.cpp/h** — the RPN number-crunching engine: stack entry/manipulation (`enter_number`, `enter_enter`, `enter_swap_xy`, `enter_rotate`, ...), 1-arg/2-arg function application (`apply_func_1to1`, `apply_func_2to1`), memory registers (`apply_memory_rcl/sto/clr`), shift-layer state, and LCD stack/input rendering (`LCDDrawStackAndMem`, `LCDDrawInput`, `LCDDrawCalcStatus`).
- **lcd.cpp/h** + **fonts.h** — driver for the ERM19264_UC1609 LCD (SPI), adapted from Gavin Lyons' ERM19264_UC1609 library. `fonts.h` holds the bitmap font table used for on-screen digits/letters/mnemonics.
- **programming.cpp/h** — "program mode" (record/replay keystrokes with control flow: IF/ELSE, CASE/WHEN, FOR/NEXT, WHILE/WEND, DO/LOOPWH). Currently **design notes only** in `programming.h`'s trailing comment block — not yet implemented (`programming.cpp` is a 1-line stub).
- **config.cpp/h** — "config mode" (battery voltage display, contrast, backlight, stack depth/mode, card switching, program import/export, debounce tuning). Also currently **design notes only** in comments — not yet implemented.
- **backlight.cpp/h** — PWM backlight on/off and duty cycle (TCA0 on `PIN_PA1`).
- **util.cpp/h** — battery voltage measurement (`setupBattVoltMonitor()`/`read_batt_voltage_mv()`), wired into config mode's battery-voltage screen.
- **avrducore/** — hand-rolled replacement for the Arduino/DxCore core (clock init, CCP-protected writes, fuses, GPIO, SPI0). See "Firmware: build & flash" above.

### Key architectural concepts

- **`action` struct** (`cards.h`): `{keycode, fct (function pointer), mnemonic[5]}`. `mnemonic` indexes into the font table for displaying the action's label in programming mode.
- **Modes**: `enum calc_prog_config_modes { calc_mode, prog_mode, config_mode }` — the calculator's top-level mode.
- **Shift layers**: `enum layers { baseLayer, fLayer, gLayer, hLayer }`, tracked in the global `shift` variable; a shift layer is exited back to `baseLayer` after any non-shift key is processed (see the shift-reset logic at the end of `loop()` in `main.cpp`).
- **Memory modes**: `mem_recall_mode` / `mem_store_mode` / `mem_clear_mode` booleans short-circuit normal action dispatch in `loop()` to instead call `apply_memory_rcl/sto/clr(r, c)` directly with the raw key position.
- Many design decisions are written as pseudocode/comments directly in the header files (`main.h`, `programming.h`, `config.h`, `cards.cpp`) before being implemented — read these comments first when extending a mode, they usually already describe the intended control flow.
- Power management is central to the design: the MCU sleeps between keypresses (`SLEEP_MODE_STANDBY`), wakes via port interrupts on column pins, and a full LCD/MCU power-down path exists (`power_down()` in `main.cpp`, `SLEEP_MODE_PWR_DOWN`).

## PCB (KiCad)

- `pcb/pcbcalc/` — the actual MiyoCalc40 calculator board (`miyocalc40.kicad_pro`/`.kicad_sch`/`.kicad_pcb`).
- `pcb/pcbbase/` — a base/reference board project.
- `pcb/lib_fp.pretty/` — project-specific KiCad footprints.
- `pcb/lib_sch/` — project-specific KiCad schematic symbol library.
- `pcb/bom/` — bill of materials.
- `pcb/printouts/` — rendered schematic/PCB/3D screenshots.
